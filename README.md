# QAting 사용자 가이드

> **3팀 · 안캡잘부** — 아주대학교 소프트웨어학과 2026-2 캡스톤디자인
> **서비스:** QAting — Figma 시안과 실제 코드를 비교해 디자인 QA 이슈를 찾고, 담당 팀 배정 → 수정 → 재검증까지 한곳에서 관리하는 QA 자동화 서비스
> **접속:** **https://acjb-qating.com** (리뷰 기간 11/11(수) ~ 11/18(수) 동안 운영)

## 1. 서비스 소개

**대상 사용자**
QA 전담 인력 없이 디자이너·프론트엔드·백엔드·기획이 QA를 나눠 맡는 소규모 웹 제품팀(학생 팀 프로젝트, 스타트업 등).

**해결하려는 문제**
"시안이랑 색이 달라요", "여기 간격이 이상해요"를 메신저로 주고받다 보면 어느 화면·어느 요소인지 다시 묻고, 고쳤는지 목록을 직접 확인하고, 다시 확인할 때 재현 방법을 또 적는 왕복이 반복됩니다. 인터뷰 12건에서 이 왕복이 QA 라운드마다 되풀이된다는 것을 확인했습니다.

**이번 MVP에서 쓸 수 있는 기능**

| 기능 | 하는 일 |
| --- | --- |
| Figma·GitHub 연결 | Figma 시안 페이지(또는 섹션)와 공개 GitHub 저장소를 프로젝트에 연결 |
| 비교 분석 | AI가 Figma 화면·요소와 그것을 그리는 코드 파일·컴포넌트를 짝지음 |
| 첫 QA (자동) | 짝지은 요소마다 Figma 값과 코드 값을 비교해 **둘 다 확인된 차이만** 이슈로 저장 (간격·여백 / 색상·타이포그래피 / 모서리 / 고정 문구) |
| 이슈 상세·코드 추적 | 디자인 기준값 vs 구현값, 문제 코드 위치(파일·줄), 그 줄이 들어온 커밋·PR |
| 담당 팀 배정·진행 상태 | 이슈에 담당 팀을 지정하고, 그 팀 멤버가 수정 시작 → 수정 완료로 상태 변경 |
| Re-QA (자동 재검증) | 수정 완료된 이슈를 같은 위치에서 다시 비교해 해결(PASS)·재실패(FAIL) 판정 |
| 실시간 QA (수동 등록) | 배포된 화면 위를 클릭하거나 스크린샷을 첨부해, 사람이 찾은 문제를 위치와 함께 등록 |
| 멤버 초대 | 구글 이메일로 팀원 초대, 프로젝트별 역할(디자인·프론트엔드·백엔드·기획) |

## 2. 접속 방법

- **주소:** https://acjb-qating.com — 설치 없이 브라우저로 사용합니다
- **지원 환경:** 데스크톱(노트북) **Chrome 최신 버전** 권장. 화면 폭 1280px 이상에서 가장 잘 보입니다(모바일은 지원하지 않음)
- **계정:** 구글 계정으로 로그인합니다. 처음 로그인하면 계정이 자동으로 만들어집니다
- 로그인이 안 되면 7절의 문의처로 알려 주세요

## 3. 핵심 기능 체험 (샘플 프로젝트, 약 15분)

**역할:** 작은 웹 서비스 팀의 **프론트엔드 개발자 겸 프로젝트 소유자**
**목표:** 시안과 구현의 차이를 자동으로 찾고 → 담당 팀을 정하고 → 수정 완료 후 재검증 결과까지 확인하기

**샘플 데이터** (저희 팀이 준비한 시안과 코드입니다. 별도 준비 없이 그대로 붙여 넣으면 됩니다)

| 항목 | 값 |
| --- | --- |
| Figma 링크 | `https://www.figma.com/design/GBZhzBWLOVirx9MMd5zddI/%EC%95%88%EC%BA%A1%EC%9E%98%EB%B6%80-%EC%BA%A1%EC%8A%A4%ED%86%A4%EB%94%94%EC%9E%90%EC%9D%B8?node-id=757-66757` (페이지 "test", 화면 10개) |
| GitHub 저장소 | `https://github.com/tjfakstn/ACJB` |
| 분석할 브랜치 | `main` |
| 배포 주소 (실시간 QA용) | `https://acjb-qating.com` |

> 비교 분석과 첫 QA는 AI(Claude)를 호출해서 저희 팀 비용이 듭니다(샘플 기준 1회 약 5~7천 원). **한 분당 프로젝트 1개만** 만들어 주세요.

### 단계별 순서

**1) 로그인**
https://acjb-qating.com 에서 [로그인하기]를 누르고 구글 계정을 고릅니다. 로그인하면 **모든 프로젝트** 화면으로 이동합니다.

**2) 프로젝트 만들기**
1. [+ 새 프로젝트]를 누르고 프로젝트 이름을 입력합니다(예: `3팀 체험 - 홍길동`).
2. 멤버 초대: 같이 체험할 사람이 없으면 **[나중에 하기]**를 누릅니다.
3. Figma·Git 연결: 위 표의 **Figma 링크**, **GitHub 저장소**, 브랜치 `main`을 넣고 연결합니다.
   - 연결에 성공하면 Figma 파일 이름과 페이지 이름("test")이 표시됩니다.

**3) 비교 분석** (약 1분)
- 연결을 마치면 바로 비교 분석 화면으로 넘어갑니다. "디자인 구조 분석"과 "UI 코드 분석"이 차례로 완료됩니다.
  - 화면을 닫았거나 실패했다면, 프로젝트 홈의 "최근 AI 분석"에서 [비교 분석 시작] 또는 [다시 시도]를 누릅니다.
- 왼쪽 메뉴 **[디자인-코드 매핑]**에서 Figma 화면마다 어떤 코드 파일·컴포넌트와 짝지어졌는지 확인합니다.

**4) 첫 QA 실행** (약 5~7분)
1. 왼쪽 메뉴 **[디자인 QA]**로 갑니다. 검증 범위 4개(간격·여백, 색상·타이포그래피, 모서리, 고정 문구)를 모두 체크하고 **[첫 QA 실행]**을 누릅니다.
2. 실행 중에는 "Figma 요소 N/M개 비교" 진행률이 보입니다. 다른 화면으로 가도 서버에서 계속 진행됩니다.
3. 끝나면 "최초 검사 완료"와 함께 **[QA 결과 보기]** 버튼이 나옵니다.

**5) 이슈 확인과 담당 팀 배정**
1. **[QA 결과]**에서 이슈를 하나 고르면, 오른쪽에 상세가 열리고 위쪽에 그 요소의 Figma 시안이 표시됩니다.
2. 이슈 상세 페이지에서 다음을 확인합니다.
   - **디자인 기준 vs 구현 실제값**(예: 색상 `#0072DC` vs `#1A73E8`)
   - **연결 코드 파일**: 값을 읽은 파일과 줄 번호. 누르면 GitHub로 이동합니다.
   - **GitHub 커밋·PR**: 그 줄이 들어온 커밋과 PR
3. **[담당 팀 지정]**에서 `프론트엔드`를 고릅니다.

**6) 수정 진행 상태 바꾸기**
- 진행 상태는 **그 담당 팀 역할을 가진 멤버만** 바꿀 수 있습니다. 프로젝트를 만든 사람은 역할이 비어 있으니 먼저 역할을 정합니다.
  - **[프로젝트 홈]** 멤버 카드의 **[멤버 관리]**에서 내 역할을 `프론트엔드`로 바꿉니다.
- 이슈 상세에서 **[수정 시작]**을 누르고, 이어서 **[수정 완료로 변경]**을 누릅니다.

**7) Re-QA (자동 재검증)**
- **[디자인 QA]**에서 **[Re-QA 실행]**을 누릅니다. 수정 완료된 이슈를 같은 Figma 요소·같은 코드 위치에서 다시 비교합니다.
- 샘플 저장소의 코드는 실제로 고치지 않았으므로, **재실패(FAIL)로 판정되고 상태가 "재확인 필요"로 돌아오는 것이 정상**입니다.
- 첫 QA 때 고르지 않은 검증 범위가 있으면, Re-QA 화면에서 더 골라 그 범위도 새로 비교할 수 있습니다.

**8) 실시간 QA — 수동으로 이슈 등록**
1. **[QA 결과]** 위쪽 배포 화면 영역에서 **[배포 주소 입력]**을 누르고 `https://acjb-qating.com`을 저장합니다(소유자만 가능).
2. **[QA 등록하기]**를 누르고, 배포 화면에서 문제가 있는 위치를 클릭합니다. 제목과 설명을 입력하고 등록합니다(심각도·기대/실제 결과는 선택).
3. 목록에 `QA-M001` 같은 번호로 수동 QA가 추가되고, 화면 위 그 위치에 핀이 표시됩니다.
   - 배포 화면이 없거나 위치를 찍기 어렵다면 **스크린샷 첨부**나 **위치 없이 등록**(화면 경로와 재현 절차를 직접 입력)도 할 수 있습니다.

## 4. 기대 결과와 확인 방법

| 단계 | 정상일 때 보이는 것 |
| --- | --- |
| 연결 | 프로젝트 홈 "연결 상태"에 Figma·GitHub 둘 다 "연결됨" |
| 비교 분석 | "최근 AI 분석: 완료". 샘플 기준 화면 10개, 요소 약 130개가 코드와 짝지어짐 |
| 첫 QA | 샘플 기준 이슈 약 50개. 각 이슈에 Figma 값·코드 값·코드 위치가 모두 있음(근거가 하나라도 없는 차이는 이슈로 만들지 않음) |
| 담당 팀·상태 | 이슈 상태가 확인 필요 → 수정 중 → 수정 완료로 바뀌고, 상태 이력에 변경자와 시각이 남음 |
| Re-QA | 이슈 상세의 재검증 기록에 FAIL과 다시 읽은 코드 값이 남고, 상태가 "재확인 필요"로 바뀜 |
| 수동 QA | 목록에 `QA-M###` 항목이 생기고 배포 화면 위에 핀이 표시됨 |

AI 판단이 섞여 있어 이슈 개수는 실행할 때마다 조금씩 다를 수 있습니다.

**다른 입력으로 다시 해 보기**
- **검증 범위 바꾸기:** 첫 QA는 프로젝트당 성공 1번입니다. 다른 범위로 처음부터 하려면 새 프로젝트를 만들거나, Re-QA에서 범위를 추가합니다.
- **본인 프로젝트로 해 보기:** 5절을 참고해 본인 팀의 Figma·GitHub를 연결합니다.
- **팀원과 같이:** 멤버 초대로 다른 사람을 `디자인` 역할로 초대하면, 담당 팀 배정과 역할별 권한 차이를 함께 볼 수 있습니다.

## 5. 본인 프로젝트로 사용하기

본인 팀의 시안과 코드로도 쓸 수 있습니다. 아래 조건을 확인해 주세요.

| 항목 | 조건 |
| --- | --- |
| Figma | 최종 시안만 담은 **페이지 또는 섹션 링크**(`figma.com/design/...?node-id=...`). 페이지는 [공유하기], 섹션은 우클릭 [링크 복사]로 얻습니다. 프레임 링크나 프로토타입 링크는 쓸 수 없습니다 |
| Figma 접근 권한 | QAting 서버가 그 파일을 읽을 수 있어야 합니다. Figma 파일의 [공유]에서 **"링크가 있는 모든 사용자 → 보기 가능"**으로 설정하고, 공유 설정의 **"뷰어의 복사·공유·내보내기 허용"**도 켜 주세요(꺼져 있으면 볼 수는 있어도 QAting이 시안 값을 읽지 못합니다. 파일 소유자만 바꿀 수 있습니다). 학교·회사 조직 파일처럼 외부 링크 공유가 막혀 있으면 연결이 안 될 수 있으니, 그때는 7절 Issues로 알려 주세요 |
| GitHub | **공개 저장소**만 가능합니다. 주소는 `https://github.com/조직/저장소`까지만 넣고(`/tree/브랜치` 주소는 안 됨), 브랜치는 연결한 뒤 드롭다운에서 고릅니다. 웹 프론트엔드 코드(`.tsx`·`.jsx`·`.ts`·`.js`·`.vue`·`.svelte`)가 있어야 합니다 |
| 크기 | UI 코드 파일 300개·100만 자 이하, 화면 1,000개 이하 |
| 비교되는 코드 | Tailwind CSS 클래스, 컴포넌트가 import한 CSS·SCSS·LESS·CSS modules 파일의 선언, styled-components·emotion, 인라인 `style`의 값과 코드에 적힌 고정 문구를 읽습니다. 변수·보간(`${...}`)·`calc()`로 정한 값은 비교하지 않습니다 |

- **비용 문제로 화면 10개 안팎의 섹션으로 연결해 주세요.** 화면 수에 비례해 시간과 비용이 늘어납니다(화면 10개 기준 첫 QA 약 5~7분).
- 배포 주소가 없어도 됩니다. 이때 실시간 QA 화면은 비어 있고, 수동 QA는 스크린샷 첨부나 위치 없이 등록하면 됩니다.

## 6. 제한 사항과 알려진 문제

**MVP에서 아직 안 되는 것**
- **알림 화면:** 담당 팀 배정·수정 완료·재검증 실패 알림은 서버에 저장되지만, 오른쪽 위 종 아이콘은 아직 동작하지 않습니다.
- **앱(AOS·iOS) 프로젝트:** 웹 화면과 웹 프론트엔드 코드만 지원합니다.
- **GitHub 이슈·PR 생성:** GitHub는 읽기만 합니다. 이슈를 GitHub로 내보내지 않습니다.
- **첫 QA는 프로젝트당 성공 1번:** 다시 처음부터 비교하려면 새 프로젝트를 만듭니다.

**사용 제한**
- **비교하지 않는 값:** 크기·위치·레이아웃, 그림자·글꼴, 투명도 있는 색, `hover:`·`md:`·`:hover`·`@media` 같은 상태·반응형 변형, 데이터로 그리는 문구, em·% 단위
- **배포 주소 제한:** 실시간 QA의 배포 주소로 `localhost`나 사설 IP는 쓸 수 없고, 인터넷에 공개된 주소만 됩니다. 다른 사이트 안에 표시되는 것을 막아 둔 사이트는 화면 대신 스크린샷 첨부 방식으로 바뀝니다.
- **실행 횟수:** 비교 분석과 첫 QA는 AI 호출 비용이 들어 저희 팀이 사용량을 지켜보고 있습니다. 과도하게 반복 실행하면 잠시 막을 수 있습니다.

**알려진 문제와 해결 방법**

| 증상 | 해결 |
| --- | --- |
| 갑자기 로그인 화면으로 돌아감 | 서버를 업데이트하면 로그인이 풀립니다. 다시 로그인해 주세요 |
| Figma 연결 시 "접근 권한 없음" | Figma 파일이 "링크가 있는 모든 사용자 → 보기 가능"인지 확인해 주세요(5절). 그래도 안 되면 Issues로 알려 주세요 |
| Figma 연결 시 "내보내기를 막아 두었어요" | 파일 소유자가 [공유] 설정에서 "뷰어의 복사·공유·내보내기 허용"을 켜야 합니다(5절) |
| GitHub 연결 시 "접근 권한 없음" | 비공개 저장소이거나 주소가 틀린 경우입니다 |

### 로컬 실행

준비물: Git, Docker Desktop, JDK 17 이상(Gradle이 Java 21을 내려받음), Node.js 20.19 이상 또는 22.12 이상.

```bash
git clone https://github.com/tjfakstn/ACJB.git
cd ACJB/backend
cp .env.example .env        # Google OAuth·DB 비밀번호·Figma 토큰·Anthropic 키를 채운다(설명은 .env.example)
docker compose up -d        # MySQL 8.4
./gradlew bootRun           # http://localhost:8080
```

```bash
cd ACJB/frontend
npm install
npm run dev                 # http://localhost:5173
```

- 테스트: `cd backend && ./gradlew test` / 프론트 빌드: `cd frontend && npm run build`
- 운영 배포 구성과 절차: [deploy/README.md](deploy/README.md)
