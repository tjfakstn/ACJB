# 프로젝트·멤버·초대 화면

Figma `UI Design - Refined` › "전체 서비스 최종 통합 UI"(605:30464) 중 지금 스펙(`docs/SPEC.md`)과 서버 API가 있는 화면만 구현했다(2026-11-06, 11-07 흐름 재정의 반영).

| 라우트 | 화면 | 시안 |
| --- | --- | --- |
| `/app/projects` | 프로젝트 목록·빈 상태 (`pages/ProjectsPage.tsx`) | U01-03, U01-A1 |
| (팝업) | 새 프로젝트 만들기 → 만드는 중 → 완료, 이름 미입력·입력 오류·생성 실패 (`CreateProjectDialog`) | U01-04~06, U01-B1~B3 |
| `/app/projects/:id` | 작업공간 홈 — 시작 체크리스트·상태별 이슈 수·멤버·연결 상태 (`pages/WorkspacePage.tsx`) | WS-01·01N·01M·02 |
| `/app/projects/:id/members` | 멤버 관리 + 이메일 초대, 역할 변경(소유자), 재전송(만료 7일 연장) (`pages/MembersPage.tsx`, `members/InviteDialog`) | MEM-02·02R·06 |
| `/invitations/:token` | 초대 메일 링크 — 확인·수락, 만료·취소·이미 수락, 잘못된 링크 (`pages/InvitationPage.tsx`) | U02-B2, U02-B3 |

API는 `src/lib/api.ts` 한 곳에서 부른다(CSRF 헤더, `{success,data,error}` 응답, `error.code`로 분기).

## 시안과 다르게 한 것 (스펙에 맞춤 — 오단비·최유정 확인 필요)

- **역할은 수락할 때 본인이 고른다**: 시안은 초대하는 사람이 정한다. 이후 변경은 소유자만(시안과 같음, SPEC AC24)
- **프로젝트 설명 없음**: 서버에 설명 필드가 없다
- **새 프로젝트 마법사**: 정보(PRJ) → 멤버 초대(INV, 이메일만 — 역할은 수락할 때 고름) → Figma·Git 연결(CON, 공개 GitHub 저장소만 — GitHub App 없음)을 한 팝업에서 진행한다
- **비교 분석(CON-06)·첫 QA는 아직 없다**: [프로젝트 시작하기]는 작업공간 홈으로 가고, 작업공간의 [첫 QA 실행]은 잠겨 있다(AC22·AC23 구현 전)
- **목록 카드의 QA 결과·FAIL 건수·마지막 분석 시각, 상태 필터·정렬 없음**: 내려줄 API가 없다. 목록은 서버가 name asc로 고정
- **초대는 이메일 한 명씩**(U02-01~05의 여러 명·역할 지정 대신), **거절·재요청 버튼 없음**, **초대 실패 탭 없음**
- **작업공간 홈의 QA Queue 목록·생성일·QA 실행 이력 건수 없음**: 상태별 이슈 수로 대신한다. 왼쪽 메뉴의 QA 화면·연결 관리는 "준비 중"
- **초대를 수락하면 그 프로젝트 작업공간 홈으로 간다**(GST-03)

## 로그인 뒤 돌아가기

서버는 로그인에 성공하면 항상 프론트의 `/`로 보낸다. 초대 링크에서 로그인하면 `sessionStorage`에 경로를 적어 두고, `/`(랜딩)가 로그인 상태를 확인해 그 경로나 `/app/projects`로 보낸다.
